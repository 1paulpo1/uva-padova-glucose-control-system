# Terminology: Validation vs Synthetic Study

This project historically used non-standard folder names. To avoid confusion,
the repository was renamed in 2026-09 (Variant A).

| Old (pre-2026-09) | New (public) | What it actually does | Standard ML term |
|---|---|---|---|
| `validation/` | `real_world_validation/` | Offline identification on **real CGM** (T1DEXI / OhioT1DM) via `test_real_data`. No ground truth; Gates A/B/C diagnose identifiability from residuals. | Real-world validation / hold-out evaluation |
| `crossval/` | `synthetic_study/` | Identification on **virtual patients** generated by the simulator itself (`synthetic_data_generator.hpp`, `virtual_patient.*`). Ground truth `θ_true` is known, so recovery error `|θ_rec - θ_true|` and coverage can be measured. | Synthetic identifiability / recovery study |

**Why the rename?** In ML, “cross-validation” usually means K-fold splits of real data. Here `crossval` meant “validate the identifier against its own simulator” — a recovery/observability study, not K-fold. The new names are unambiguous.

**Backward compatibility:** `real_world_validation/run_validation.py --help` and `synthetic_study/cross_validate --help` still accept the same flags. Old output filenames (`crossval_results.json`) are accepted as aliases for `synthetic_results.json`.

**Where to look:**
- Real data: `real_world_validation/test_real_data.cpp`, `real_world_validation/batch_runner.py`, `real_world_validation/parsers/`
- Synthetic: `synthetic_study/virtual_patient.hpp:70`, `synthetic_study/cross_validate.cpp`, `include/uva_padova/synthetic_data_generator.hpp:76`
- Analysis: both share plotting code (`synthetic_study/analyze_results.py` is the source; `real_world_validation/analyze_results.py` re-exports ground-truth-free plots)
